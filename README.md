# MiniTavern

MiniTavern is a self-hosted chat interface for OpenAI-compatible language model
APIs. It supports characters, personas, prompt templates, branching chats, and
SillyTavern PNG card import and export.

The server is built with Node and SQLite, and the client uses SolidJS. Chat state
lives on the server and is synchronized over WebSocket, so the same conversation
can be open on several devices without separate client-side copies.

## Features

- Branch conversations by editing an earlier message or generating another reply.
  A zoomable tree view shows the complete history.
- Manage characters, personas, system prompts, and prompt templates. Templates
  support macros, speaker names, persona opt-out, steering instructions, and
  reasoning or message prefills. Characters can override their prompt and
  template.
- Organize characters into folders, import or export SillyTavern PNG cards, and
  duplicate saved characters, personas, prompts, templates, and endpoints.
- Configure multiple API endpoints with separate models, sampling options, and
  assistant-prefill behavior. Individual conversations can override the active
  endpoint.
- Stream replies and reasoning, inspect the exact upstream prompt, and retry
  interrupted generations from their partial output. A continue button can also
  finish a draft in the composer or extend the last assistant reply.
- Optionally generate the next unread reply in the background so it is ready
  when you swipe forward.
- Search message content and conversation titles. Conversations can be copied or
  exported as self-contained JSON, including their branches and generated images.
- Generate chat images and character or persona avatars through ComfyUI. The
  bundled image plugin supports reusable prompt presets, multiple workflows, live
  previews, and image alternatives.
- Use the responsive web client on desktop or mobile. Changes and active streams
  appear on every connected client.

The production setup runs entirely in Docker; Node does not need to be installed
on the host.

## Production

```sh
mkdir -p data certs
docker compose up --build -d
```

The checked-in Compose file expects `certs/cert.pem` and `certs/key.pem`; place
your TLS certificate and private key there before starting. It also joins the
external Docker network `my-bridge-network`, which must already exist. Open
`https://<host>:5487` after the container starts. State lives in `./data`.

### Backups

MiniTavern uses SQLite WAL mode. Do not copy `minitavern.db` while the server is
running: recent committed changes can still be in `minitavern.db-wal`, so a raw
copy can lose new rows or resurrect deleted ones.

Create a transactionally consistent database snapshot with SQLite's online
backup mechanism:

```sh
docker compose exec minitavern node server/src/backup.ts /data/backups/minitavern-$(date +%F).db
```

The command refuses to overwrite an existing backup and stores it with mode
`0600`. Generated images and avatars are separate files; for a complete disaster
recovery copy, stop MiniTavern and copy the whole `./data` directory, including
`avatars`, `images`, and the database snapshot.

### Network allowlist

MiniTavern can restrict HTTP and WebSocket access by source IP. The checked-in
Compose files set `MINITAVERN_IP_ALLOWLIST` to an empty string, which allows all
addresses. Replace that value in the Compose file with the addresses or CIDR
ranges that should have access:

```sh
MINITAVERN_IP_ALLOWLIST=127.0.0.1/32,::1/128,192.168.1.20/32,192.168.1.0/24
```

If the variable is omitted instead, MiniTavern allows loopback, RFC 1918 private
networks, IPv6 unique-local addresses, and link-local addresses. Keep
`172.16.0.0/12` when using Docker-internal tools or the mock service.

For an additional application-level gate, set an access password under **Settings > General**.
No password is configured by default. When enabled, API requests, generated media, avatars, and
WebSocket connections require an authenticated HTTP-only session cookie; the IP allowlist still
applies independently. Login sessions last 30 days and survive ordinary server/container restarts;
changing or removing the password revokes them immediately.
Use HTTPS when the password will cross an untrusted network.

### HTTPS

TLS is enabled in `docker-compose.yml`. Plain HTTP requests on port 5487 are
redirected to HTTPS, WebSockets use `wss://`, and the certificate is reloaded
when either file changes. To run without TLS, remove `TLS_CERT_PATH`,
`TLS_KEY_PATH`, and the `./certs` mount from the Compose file.

### ComfyUI (optional)

Both Compose files attach the containers to an external Docker network named
`my-bridge-network` so the server can reach a ComfyUI container as
`http://comfy:8588`. If you don't run ComfyUI, either create the network
(`docker network create my-bridge-network`) or remove the `networks` blocks;
if your ComfyUI has another name/port, adjust the ComfyUI URL in
Settings > Tools > Image Generation.

To render images: export your workflow via ComfyUI's "Save (API Format)",
paste it in Settings > Tools > Image Generation, and replace the sampler seed
with `{{seed}}` and the positive prompt text with `{{prompt}}` (the field
validates the JSON and checks both macros live). Multiple named workflows are
supported; the selected one is what `/image` uses.

## First-run setup

1. Open Settings > **Endpoints**, add your OpenAI-compatible API, and configure
   its sampling settings. The base URL should include the path through `/v1`.
   Pick a model if the API requires one, or leave it blank to use the endpoint's
   default. Select the endpoint as active at the top of the same page.
2. Start a conversation with the built-in **Assistant** character.
3. Add or import characters as needed. **Prompts**, **Templates**, and
   **Personas** are optional and can be selected as defaults on their respective
   settings pages.

## Shortcuts and commands

- **Enter** sends and **Shift+Enter** inserts a newline. On touch layouts, use the
  send button; Enter always inserts a newline.
- **Up** in an empty composer edits your last message. **Ctrl/Cmd+Enter** in a
  message editor submits the edit as a new branch, and **Escape** cancels.
- **Left/Right** move between alternatives for the last image or assistant reply.
  Moving right past the end generates another. Horizontal swipes do the same on
  touch screens.
- `/char <name>` changes the assistant speaker name. `/del <n>` removes messages
  from the end, including their swipes and descendants. `/delchat` deletes the
  conversation.
- `/image`, `/imagechar`, and `/imageface` generate different kinds of image
  prompts. Each accepts an optional instruction and renders through ComfyUI when
  a workflow is selected under Settings > Tools > Image Generation.

## Development

```sh
mkdir -p data-dev
docker compose -f docker-compose.dev.yml run --rm --no-deps server npm install
docker compose -f docker-compose.dev.yml up
```

To include the fake OpenAI-compatible API, start the stack with
`docker compose -f docker-compose.dev.yml --profile mock up`.

- Client (Vite, HMR): `http://localhost:5173`, or HTTPS when the certificate
  files are present
- Server API: `http://localhost:5488`
- Mock OpenAI API endpoint (with `--profile mock`): base URL `http://mock:9800/v1`, any API key.

Typecheck:

```sh
docker compose -f docker-compose.dev.yml run --rm --no-deps server npm run check
docker compose -f docker-compose.dev.yml run --rm --no-deps server npm run format:check
```

End-to-end tests run against a throwaway server+mock pair inside one container - they are
destructive and refuse to start without explicit targets, so never point them at a live instance:

```sh
docker compose -p minitavern-e2e -f docker-compose.dev.yml run --rm --no-deps \
  -e DATA_DIR=/tmp/e2e-data -e E2E_BASE=http://127.0.0.1:15487 -e E2E_MOCK=http://127.0.0.1:19800/v1 \
  server sh -c 'PORT=15487 node server/src/index.ts >/tmp/server.log 2>&1 & \
    PORT=19800 node scripts/mock-openai.ts >/tmp/mock.log 2>&1 & \
    sleep 2; node scripts/e2e.ts; ec=$?; tail -5 /tmp/server.log; exit $ec'
docker network rm minitavern-e2e_default
```
